## 1. 시스템 아키텍처 및 컴포넌트

```text
[사용자 (모바일/데스크톱 브라우저)]
        │ HTTPS
        ▼
[Cloudflare Workers (mudeal · vinext Next.js App Router + worker/index.ts)]
  ├─ 공개 읽기 API (/api/v1/home, /shows, /shows/[id]): Edge Cache (s-maxage=60)
  ├─ 보안 헤더: X-Content-Type-Options, Referrer-Policy, X-Frame-Options
  ├─ DB: Cloudflare D1 (mudeal-db · Drizzle ORM · 19개 테이블)
  ├─ 파일 스토리지: Cloudflare R2 (mudeal-evidence · 선택 바인딩, 회원 제보 증빙)
  └─ 5-Cron 배치 (Workers Free 5개 / 호출당 50 Subrequests 준수):
       ├─ */15 * * * *  : 만료 딜·종료 공연 상태 전환 (expiry.ts)
       ├─ 0 16 * * *    : KOPIS 일일 동기화 (01:00 KST) + 일일 DB/R2 보존 정리 (retention.ts)
       ├─ 10 */6 * * *  : NOL + L.TICKET 수집 (<= 25 Subrequests)
       ├─ 25 */6 * * *  : YES24 수집 (<= 23 Subrequests)
       └─ 40 */6 * * *  : Gemini Vision OCR(<=5건) + 줄거리 보강(<=2건, 2초 간격, 429 즉시 중단)
```

## 2. 환경 변수 · 시크릿 · 바인딩 관리

### 2.1 Workers Secrets (`npx wrangler secret put <KEY>`)

| 키 | 필수 여부 | 용도 | 비고 |
|---|---|---|---|
| `JWT_SECRET` | **필수 (운영)** | HS256 액세스/리프레시 토큰 서명 | 누락 시 운영 Fail-Fast (32바이트 이상 랜덤 문자열 권장) |
| `KOPIS_API_KEY` | **필수** | KOPIS 공연·정가·출연진 일일 동기화 | 일일 호출량 여유 |
| `GEMINI_API_KEY` | **필수 (OCR)** | 공지 이미지 Vision OCR · 줄거리 추출 | 무료 `Flash Lite`(15 RPM / 500 RPD) 1순위 사용 |
| `KAKAO_CLIENT_ID` / `KAKAO_CLIENT_SECRET` | **필수 (로그인)** | 카카오 OAuth2 소셜 로그인 | 콜백: `https://<도메인>/api/v1/auth/oauth/kakao/callback` |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | 선택 | 구글 OAuth2 소셜 로그인 | 콜백: `https://<도메인>/api/v1/auth/oauth/google/callback` |
| `ADMIN_OAUTH_EMAILS` / `ADMIN_KAKAO_IDS` | **필수 (관리자)** | 관리자 권한 부트스트랩 (이메일 인증 검증된 계정만 허용) | 콤마(`,`) 구분 |

### 2.2 일반 변수 (`wrangler.jsonc` `vars`)
- `OCR_DAILY_LIMIT`: `"100"` (기본값. AI Studio 무료 RPD 확인 후 80% 이하 유지)

### 2.3 Cloudflare R2 활성화 및 30일 자동 만료 설정 (TD-002)

> [!NOTE]
> 2026-11-27 확인 결과 계정에 R2가 아직 활성화되지 않아(`code: 10042`) 현재 `EVIDENCE_BUCKET` 바인딩 없이 안전하게 동작 중입니다(증빙 이미지는 선택 항목). 회원 제보 이미지 업로드를 활성화할 때 아래 순서대로 1회만 설정하세요.

1. Cloudflare Dashboard → **R2 Object Storage** 메뉴에서 R2 무료 티어(월 10 GB) 활성화
2. 버킷 생성 및 **30일 자동 만료(Lifecycle Rule)** 적용:
   ```bash
   npx wrangler r2 bucket create mudeal-evidence
   npx wrangler r2 bucket lifecycle add mudeal-evidence \
     --id expire-report-evidence-30d \
     --prefix reports/ \
     --expire-days 30
   ```
3. `wrangler.jsonc`에 바인딩 추가 후 재배포:
   ```jsonc
   "r2_buckets": [
     {
       "binding": "EVIDENCE_BUCKET",
       "bucket_name": "mudeal-evidence"
     }
   ]
   ```
*(코드 측 일일 정리 배치 `purgeExpiredRetentionData`도 처리 완료 30일 경과 R2 오브젝트를 이중으로 정리합니다.)*

## 3. 배포 및 DB 마이그레이션 절차

```bash
# 1. 검증 (CI 동일 게이트)
npm run typecheck
npm test
npm run build

# 2. 원격 D1 마이그레이션 적용 (스키마 변경 시)
npx wrangler d1 migrations apply mudeal-db --remote

# 3. Workers 배포
npx wrangler deploy

# 4. 배포 직후 스모크 체크
curl -I https://<배포도메인>/
curl -I https://<배포도메인>/api/v1/home
```

- 확인 포인트:
  - `/` 응답에 `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `X-Frame-Options: DENY` 포함
  - `/api/v1/home`·`/api/v1/shows` 응답에 `Cache-Control: public, max-age=30, s-maxage=60, stale-while-revalidate=120` 포함
  - `/admin/deals`에서 동기화 이력 정상 여부 및 5-Cron 트리거 등록 상태(Cloudflare Dashboard → Triggers) 확인

## 4. 백업 및 복구

### 4.1 일상 백업
- **자동**: Cloudflare D1 Time Travel (무료 **7일** 시점 복구 기본 제공)
- **월간 수동 덤프 (권장)**:
  ```bash
  npx wrangler d1 export mudeal-db --remote --output=backup-mudeal-YYYYMM.sql
  ```
  *(덤프 파일은 개인정보·토큰 해시를 포함하므로 Git 저장소에 절대 커밋하지 않고 암호화 로컬/프라이빗 스토리지에 보관)*

### 4.2 장애 시 시점 복원
```bash
# 현재 북마크 확인 후 특정 시각으로 복원
npx wrangler d1 time-travel info mudeal-db
npx wrangler d1 time-travel restore mudeal-db --timestamp="YYYY-MM-DDTHH:MM:SSZ"
```

## 5. 일상 운영 콘솔 및 점검 명령

- **어드민 웹 콘솔**:
  - `/admin/reports`: 사용자 제보 승인/반려 + OCR 초안 원본 이미지 대조·구조화 보정 승인 + `FAILED`/`NEEDS_REVIEW` OCR 재시도
  - `/admin/deals`: 수동 딜 CRUD(`admin_locked` 자동 보호) · 수동 동기화 트리거(KOPIS/채널/OCR/마감) · 배우 병합 · 홈 배너 큐레이션
  - `/admin/issues`: 사용자 품절/가격 오류 신고 처리(`EXPIRE_DEAL` 시 자동 `admin_locked=1`)
- **실시간 로그 모니터링**:
  ```bash
  npx wrangler tail mudeal
  ```
