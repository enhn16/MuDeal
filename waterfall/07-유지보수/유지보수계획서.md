## 1. 운영 전제 및 무료 인프라 한도 관리

MuDeal은 MVP 단계에서 **월 0원 무료 인프라**를 최우선으로 운영하며, 트래픽·데이터가 아래 임계치에 도달할 때만 유료 전환을 검토합니다.

| 리소스 | 무료 한도 | 경고 임계치 (70%) | 현재 설계 소비량 (예상) | 초과 시 동작 |
|---|---|---|---|---|
| **Cloudflare D1 용량** | **500 MB** / DB | 350 MB | 자동 정리 적용 시 회원 1만 명 기준 **40~60 MB** | 쓰기 실패 → Retention 정리로 예방 |
| **Cloudflare D1 일일 읽기** | **500만 행 / 일** | 350만 행 / 일 | DAU 1,000명 기준 ~50~150만 행 / 일 | UTC 자정까지 쿼리 차단 (과금 없음) |
| **Cloudflare D1 일일 쓰기** | **10만 행 / 일** | 7만 행 / 일 | 배치 + 사용자 활동 합산 ~3,000~10,000 행 / 일 | UTC 자정까지 쓰기 차단 (과금 없음) |
| **Cloudflare Workers Cron** | **5개** / 호출당 **50 Subrequests** | 40 Subrequests | 5-Cron 분리 완료 (호출당 최대 23~40 Subrequests) | 초과 시 해당 배치 예외 |
| **Cloudflare R2 용량** | **10 GB / 월** (Class A 100만, B 1,000만) | 7 GB | 제보 증빙 30일 정리 시 **< 500 MB** | 무료 초과분 종량 과금 → 수명주기 규칙 필수 |
| **Gemini API Free** | `Flash Lite` **15 RPM / 500 RPD**<br>`Flash` 폴백 5 RPM / 20 RPD | 일 80% / `429` 발생 | Cron 일 최대 20~28회 (`OCR_DAILY_LIMIT=100`, 2초 간격, `429` 시 즉시 중단) | `429` 반환 후 다음 Cron 자동 재개 (과금 없음) |
| **D1 Time Travel 백업** | **7일** | — | 자동 7일 시점 복구 + 월 1회 수동 SQL 덤프 보완 | 7일 이전 시점 복구 불가 |

## 2. 데이터 생명주기 및 자동 정리(Retention & Purge) 정책

### 2.1 핵심 설계 원칙: "공연은 남기고, 로그·만료 딜·임시 데이터를 비운다"

> [!NOTE]
> **구현 완료 ([expiry.ts](../../src/server/sync/expiry.ts) + [retention.ts](../../src/server/sync/retention.ts))**: 15분 Cron(`expiry.ts`)이 만료 딜·종료 공연의 상태를 전환하고, 01:00 KST 일일 Cron(`0 16 * * *`) 끝단에서 `purgeExpiredRetentionData(db)`가 아래 보존 기간이 지난 로그·세션·만료 딜·R2 증빙 이미지를 50건 청크(테이블당 500건 상한)로 자동 정리합니다.

**종료된 공연(`shows`)을 즉시 삭제하지 않는 이유**:
- 사용자의 **찜 목록(`user_show_bookmarks`)**, **배우 상세의 출연 이력(`show_actors`)**, **마이페이지 캘린더(`user_calendar_events`)**, **제보 기여 내역(`deal_reports`)**이 `shows`를 참조합니다.
- `shows` 1건은 포스터를 외부 URL 텍스트로만 저장해 약 **1.5~2 KB**에 불과합니다(연 1,000편 누적 시 약 2 MB).
- 반대로 DB 용량을 실제로 채우는 것은 **클릭 로그(`outbound_clicks`), 알림(`user_notifications`), OCR 추출 JSON(`ocr_image_jobs`), 만료 세션(`user_sessions`), 동기화 로그(`sync_runs`), 만료 딜(`deals`), R2 증빙 이미지**입니다.

### 2.2 19개 D1 테이블 + R2별 보존 및 삭제 기준

| 구분 | 테이블 / 스토리지 | 보존 정책 | 정리 방식 | 근거 및 주의사항 |
|---|---|---|---|---|
| **영구 / 회원 탈퇴 시 삭제** | `users`, `user_show_bookmarks`, `user_actor_follows`, `user_calendar_events`, `user_search_presets` | 회원 활성 기간 동안 보존 | 탈퇴(`DELETE /api/v1/me`) 시 개인화 5종·투표·R2 즉시 삭제 + `users` 익명화(`WITHDRAWN`) | 탈퇴 익명화 레코드는 1년 후 완전 파기 검토 |
| **장기 보존 (연 ~2~5 MB)** | `shows`, `actors`, `show_actors` | `ONGOING`/`UPCOMING` 상시 유지 · `ENDED`는 **종료 후 1년(365일)** 보존 | 365일 경과 `ENDED` 공연 중 **찜·캘린더·제보 참조가 0건**인 작품만 선택 삭제(`CASCADE`로 `show_actors` 동시 정리) | 배우 필모그래피·관극 기록 보호 + 저용량 |
| **단기 롤링 (즉시 정리 대상)** | `outbound_clicks` | **14일** | `clicked_at < now - 14d` 물리 삭제 | 10초 중복 방지용 원시 로그이며 누적 집계는 `deals.click_count`에 보존됨 |
| **단기 롤링** | `user_sessions` | 만료/폐기 후 **7일** | `(revoked_at IS NOT NULL OR expires_at < now) AND updated < now - 7d` 물리 삭제 | 회전·로그아웃 시 행이 계속 누적되는 테이블 |
| **단기 롤링** | `sync_runs` | **30일** | `started_at < now - 30d` 물리 삭제 | 관리자 대시보드 최근 30건·3연속 실패 감지에 충분 |
| **중기 롤링** | `user_notifications` | 읽음+미저장 **30일**, 미읽음+미저장 **90일**, 저장(`is_saved=1`) **영구** | `is_saved = 0` 조건 하에 경과 건 물리 삭제 | 마이페이지 "최근 소식 다시 보기(30일)" 정책과 일치 |
| **중기 롤링** | `ocr_image_jobs` | `DONE`/`FAILED` 후 **90일** (단, `extracted_json`은 **30일** 후 `NULL` 경량화) | 30일 경과 건 `extracted_json = NULL` 비우기 → 90일 경과 + 연결 `deals` 없는 건 삭제 | `extracted_json`이 DB 용량의 큰 비중 차지. 최근 90일 `image_hash` 유지로 중복 OCR 방지 |
| **중기 롤링** | `deals` & `deal_helpful_votes` | `EXPIRED`/`DISCARDED`/`HIDDEN` 후 **90일** | `source_type != 'USER_REPORT'`(또는 제보 기여 집계 반영 완료) 만료·폐기 딜 90일 후 삭제 (`CASCADE`로 `deal_helpful_votes`·`deal_issues` 정리) | `USER_REPORT` 제보자의 누적 기여 수 보호를 위해 `deal_reports` 원본은 유지 |
| **중기 롤링** | `deal_issues` | `RESOLVED`/`DISMISSED` 후 **90일** | 처리 완료 90일 경과 건 물리 삭제 | `OPEN` 건은 보존 |
| **장기 로그** | `audit_logs`, `deal_reports` | `audit_logs` **180일**, `deal_reports` **1년** | 180일 경과 `audit_logs` 물리 삭제, `deal_reports` 반려 건 180일 후 삭제 | 운영 감사 및 제보자 이력 확인 |
| **운영 설정** | `home_curations` | 비활성(`is_active=0`) 후 **90일** | 종료된 구 배너 수동/정기 삭제 | 행 수 극소량(< 50행) |
| **R2 오브젝트** | `mudeal-evidence` (`reports/*`) | 제보 처리(승인/반려) 후 **30일** · 고아 파일 **7일** | **Cloudflare R2 Lifecycle Rule (30일 자동 만료)** 설정 + 탈퇴 시 즉시 삭제 | R2 무료 10 GB 초과 과금 원천 차단 |

### 2.3 자동 정리 배치 구현 계획 (다음 유지보수 1순위 작업)

Workers Free 플랜의 **5-Cron 한도를 이미 사용 중**이므로, 별도 Cron을 늘리지 않고 **기존 일일 KOPIS Cron(`0 16 * * *`, 01:00 KST)** 끝단에 `purgeExpiredRetentionData(db)`를 붙입니다(HTTP Subrequest 0건, D1 쿼리 6~8건만 추가).

- **안전 장치**:
  - 1회 실행당 테이블별 `LIMIT 500` 배치 삭제(D1 일일 쓰기 10만 행 한도 보호 및 Worker CPU 급증 방지).
  - 삭제 전 `is_saved = 0`, `status IN ('EXPIRED','DISCARDED')` 등 화이트리스트 조건 필수.
  - `try/catch`로 KOPIS 동기화와 완전 격리.

## 5. 스케일업 (무료 → 유료 전환) 판단 기준

무료 운영을 유지하다가 아래 조건 중 하나라도 **월 3회 이상 반복**되면 유료 전환을 검토합니다.

1. **D1 용량 > 400 MB** (정리 배치 적용 후에도 지속 증가) 또는 **일일 읽기 400만 / 쓰기 8만 행 초과 반복** → **Cloudflare Workers Paid ($5/월)** 전환 시 D1 10 GB · 월 250억 읽기 · 5,000만 쓰기 · 30일 Time Travel · Cron 호출당 1,000 Subrequests로 대폭 확장.
2. **신규 공지 이미지가 하루 400장 이상** (Flash Lite 무료 500 RPD 초과) → Gemini 유료 티어 전환(Flash-Lite 기준 이미지 1,000장당 약 $0.1~0.3 수준으로 극저비용).
3. **R2 증빙 이미지가 30일 수명주기에도 8 GB 초과** → 업로드 시 클라이언트 WebP 압축(5MB → ~300KB) 먼저 적용해 무료 10 GB 구간을 10배 연장.
